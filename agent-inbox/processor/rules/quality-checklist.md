# Quality Checklist

一份 handoff 必须回答以下问题才算合格。Processor 在生成 processed handoff 时，应逐条检查。

## 必答问题

1. **目标是什么？** — 一句话说清楚这个 handoff 要达成什么
2. **为什么要做这个变更？** — 背景和动机
3. **应该改什么？** — 具体的代码修改方向
4. **不能改什么？** — 明确的约束和边界
5. **哪些命名/概念必须保留？** — 已有的命名约定和概念定义
6. **最小实现方向是什么？** — 最小改动方案，避免过度工程
7. **验收标准是什么？** — 至少 1 条可验证的标准
8. **风险是什么？** — 可能出问题的地方
9. **哪些问题未解决？** — 已知的不确定性

## 检查规则

### 通过条件
- 问题 1、3、7 必须有实质性回答（不能是"暂无"或空）
- 问题 4 至少有一条约束
- 问题 6 至少有一个步骤

### 降级处理
- 如果问题 2（为什么）缺失：不阻塞，但在 `processor_reason` 中提示
- 如果问题 5（命名）缺失：不阻塞，Coding Agent 应自行遵循项目约定
- 如果问题 8（风险）缺失：不阻塞，但在 agent view 中标注"风险未评估"
- 如果问题 9（未决问题）缺失：视为无未决问题

### 阻塞条件
- 问题 1（目标）缺失 → `blocked`，reason: "目标不清晰"
- 问题 3（改什么）缺失 → `blocked`，reason: "缺少代码修改方向"
- 问题 7（验收标准）缺失 → `blocked`，reason: "缺少可测试的验收标准"

## Agent View 质量要求

生成的 agent view 应满足：

1. **自包含** — Agent 读完 agent view 就能开始工作，不需要回头看 raw handoff
2. **可执行** — 每个 section 都有具体内容，不是空壳
3. **无歧义** — 避免"可能"、"也许"等模糊词（未决问题除外）
4. **格式一致** — 严格遵循 agent view 模板的 section 结构
