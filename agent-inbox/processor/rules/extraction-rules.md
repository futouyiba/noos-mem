# Extraction Rules

从 ChatGPT 讨论中提取结构化信息的规则。

## Decision 提取条件

满足以下任一条件，提取为 Decision：

1. **确定设计方向** — 讨论明确选择了方案 A 而非方案 B
2. **否决替代方案** — 讨论明确排除了某种实现方式
3. **定义系统边界** — 讨论划定了模块/系统的职责范围
4. **定义命名规范** — 讨论确定了变量名、API 名、概念名

### Decision 格式要求
- 标题应是陈述句，表达"做了什么决定"
- 内容应包含：决定了什么、为什么这样决定、排除了什么替代方案
- 如果已有知识库中存在语义相近的 decision，标记 `is_new: false` 并在内容中引用已有 decision

## Concept 提取条件

满足以下任一条件，提取为 Concept：

1. **术语反复出现** — 同一术语在讨论中出现 2 次以上
2. **跨 handoff 可复用** — 该概念可能在其他需求中被引用
3. **定义系统核心抽象** — 该概念是系统设计的基础构件
4. **未来 Agent 可能需要** — Coding Agent 理解需求时需要知道这个概念

### Concept 不提取条件
- 一次性措辞（只在特定语境下使用的临时说法）
- 低价值示例（用于解释的举例，本身不是概念）
- 临时情绪语境（讨论中的感叹、犹豫等）
- 无讨论依据的实现猜测

### Concept 格式要求
- 标题应是名词或名词短语
- 描述应是定义式的，说明"是什么"而非"怎么用"
- slug 使用 kebab-case 英文，不带日期

## Open Question 提取条件

满足以下任一条件，提取为 Open Question：

1. **未解决** — 讨论中明确表示"还没确定"、"待定"、"需要验证"
2. **可能影响实现** — 该问题的答案会改变代码实现方式
3. **需要人确认** — 需要产品/设计/用户确认的问题
4. **明确标记为不确定** — 讨论中使用了"也许"、"可能"、"不确定"等词

### blocks_ready 判断
- `true`：如果该问题不解决，Agent 无法开始实现（缺少关键信息）
- `false`：问题存在但不阻塞实现（可以先用默认方案，后续调整）

## Constraint 提取条件

满足以下任一条件，提取为 Constraint：

1. **限制 Agent 可改范围** — "不要动 X 模块"
2. **定义不做什么** — "这次不处理 Y 场景"
3. **保护兼容性** — "必须保持 Z 接口不变"
4. **性能/资源限制** — "不能超过 N ms"

## Acceptance Criteria 提取条件

满足以下任一条件，提取为 Acceptance Criteria：

1. **定义可观测行为** — "用户应该看到 X"
2. **可测试条件** — "当 A 时，B 应该为 C"
3. **编译/运行时检查** — "编译通过"、"测试通过"
4. **完成标准** — "所有 X 都应该 Y"

### Acceptance Criteria 格式要求
- 每条应是可验证的陈述
- 避免模糊词（"应该更好"、"性能提升"）
- 优先使用"当...时，应该..."的格式
